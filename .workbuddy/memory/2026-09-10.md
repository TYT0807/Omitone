## 第 13 轮：跨域帧异常打挂主循环（验证码不处理的真正根因）+ 1.0.5

- **用户反馈**：验证码弹出后日志只剩反复重复的
  `tick error {"message":"Failed to read a named property 'document' from 'Window': Blocked a frame with origin "https://mooc1.chaoxing.com" from accessing a cross-origin frame."}`
- **根因**：`_searchChaoxingJobOcs()` 里 `var knowCardWin = this._getMainWindow(); if (!knowCardWin || !knowCardWin.document)` —— **裸读跨域窗口的 document**。
  验证码/反作弊页常把主 `#iframe` 指向跨域地址，此时读 `.document` 抛 SecurityError；`_runTick` 每 250ms 调用一次 → 每轮都在验证码检测之后（当时是 `_detectPageChange` 之后）被打断 → 异常冒泡进 tick 的 catch → 本轮直接结束，后面的视频巡检/任务处理全不执行，且日志被同一条错误刷满。
  同样问题的第二处：`_ensureOcsStudyRunner()` 的 `if (!knowCardWin || !knowCardWin.document)`。
- **修复**：
  1. 新增三个安全助手（`_safeDocOf` / `_safeWinDoc(win)` / `_isFrameSameOrigin(frame)`），跨域一律返回 null，绝不抛异常。
  2. 修掉两处裸访问（`_searchChaoxingJobOcs` 用 `knowCardDoc`、`appRef._safeDocOf(frame)`、`appRef._safeWinDoc(win)`；`_ensureOcsStudyRunner` 用 `_safeWinDoc`），并把 `_runPptAudioJob` 的 `win.document` 也换掉。
  3. **`_runTick` 重排**：验证码检测放到最前（在 `_detectPageChange` 之前），并各自包 try/catch——任何单点异常不再打断整轮。
  4. 新增 `_checkBlockedByCrossOrigin()`：主 iframe 跨域 → 记录 `_mainFrameCrossOriginSince`，15s 节流 warn 日志；持续 >20s 且 `configs.blockedReload !== false` 且 `document.readyState === 'complete'` → 刷新页面恢复（180s 冷却）。新增 DEFAULT_CONFIG `blockedReload: true`。
  5. **tick 错误日志去重**：同一 message 30 秒内只记一条，并附 `err.stack` 前 3 行（便于下次精确定位），计数存 `_lastTickErrCount`。
- **版本** 1.0.4 → 1.0.5（manifest name/version/default_title、popup.html title/.ver、content.js brand）。
- 校验：page/content/popup 三文件 `node --check` 全过；全项目无 1.0.4 残留。

## 第 15 轮：音频无法播放排查修复（发现机制 + m4a/MIME 兜底）+ 1.0.7

- **用户反馈**：插件无法听音频，怀疑是 m4a 格式问题，要求修复并检查音频自动播放链路。
- **排查结论（m4a 是次要嫌疑，主因是"找不到音频元素"）**：
  1. **可见性过滤把隐藏 audio 全滤掉了（主因）**：`_findMediaInDocument` / `_getVideoEl` 都用 `visible(m) || getClientRects().length>0` 过滤。`<audio>` 常被自定义播放器隐藏（无控件/零尺寸）→ 永远找不到媒体元素 → 音频任务点直接判"media not ready"，根本不会播。
  2. **完全没有 error 事件监听**：`_videoEventHandle` 只绑 ended/loadedmetadata/play/pause/ratechange → 格式/MIME 不支持（code 4）或解码失败（code 3）**永远静默**，所以无法判断 m4a 到底能不能播。
  3. `_findMediaInDocument` 不递归子 iframe（音频播放器常嵌在 iframe 里）。
  4. 倍速自动探测对 audio 无意义（音频播放器没有"老师设置的最大倍速"菜单），还会白改速率。
- **修复**：
  - 新增 `_pickMedia(list)`：优先可见媒体，其次隐藏的 audio（隐藏 video 仍不选，避免误选无关元素）；`_isVisibleMedia(m)` 抽出。
  - `_getVideoEl` 的 findVideos 改为返回 `{visible, hiddenAudio}`，优先 visible，无可见媒体时回退 hiddenAudio。
  - `_findMediaInDocument` 加子 iframe 递归（depth ≤3，最多 8 个 frame，用 `_safeDocOf` 防跨域抛错）。
  - `_videoEventHandle` 增绑 `error` → 新增 `_handleMediaError`（记录 code/message/src/tag，日志 `media error`）；code 3/4 时触发 `_maybeRepairMediaSource`。
  - 新增 `_maybeRepairMediaSource(media)`：**m4a/MIME 兜底**——页面内 `fetch(src, {credentials:'include'})` → ArrayBuffer → 按 `_guessMediaMime`（m4a/aac→audio/mp4、mp3→audio/mpeg…）重新封装 Blob → objectURL 重设 src → load → 恢复进度 → play。跳过 blob:/m3u8，每个 src 只补救一次（`_mediaRepaired`）。
  - `_playChaoxingMediaJob`：音频任务加诊断日志 `audio task started`（src 尾 70 字符 / mime / canPlayType 探测结果 / muted）；play 失败静音重试后再失败 → 若 NotSupported 或 error.code===4 走兜底修复，成功则 `media play recovered after source repair`。
  - `_ensurePlaybackRate`：audio 跳过自动最大倍速探测，直接用 `configs.playbackRate`。
- **音频链路复核（结论：可正常运行）**：任务识别 `#video,#audio` → kind 'video' → `_playChaoxingMediaJob` → 查找(含递归/隐藏兜底) → 倍速 → 播放(静音重试+m4a兜底) → `_startVideoMonitoring`(1.5s 巡检) → ended → nextUnit；PPT 音频路径 `_startSlideMedia`/`_waitSlideAudioDone` 本身无可见性过滤，正常。
- **版本** 1.0.6 → 1.0.7（manifest/popup/content brand）。三文件 node --check 全过，无 1.0.6 残留。
