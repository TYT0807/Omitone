# 任务：把 `page.js`（9899 行 / 330 个方法）拆成多个源文件

> 这份是**给执行拆分的 AI** 的完整提示词。它自包含 —— 但你手上有仓库，
> 所以涉及细节时以仓库里的文档为准（README / AGENTS / ARCHITECTURE）。
>
> **开始前请先读**：`AGENTS.md` 全文（尤其 §2 硬性约束、§3 改完的固定动作、§5 加测试时的自问）、
> `README.md` 第一屏与 §5 代码易纠缠点、`ARCHITECTURE.md`。

---

## 0. 一句话目标

把 `page.js` 拆成可维护的多个源文件，**但不改变任何运行时行为**。
验收标准不是"看起来清爽了"，而是：**测试全绿 + 产物行为与拆分前一致**。

## 1. 现状（已勘明，不用重新摸索）

| 事实 | 数值 / 说明 |
| --- | --- |
| `page.js` 行数 | **9899 行** |
| 方法数 | **330 个**（都在一个对象字面量里） |
| 顶层结构 | **一个 IIFE**：`(function () { 'use strict'; … })();` |
| 内部结构 | 常量 → 工具函数 → **一个巨大的 `var app = { …330 个方法… }`** → `window.xxtAI = {…}` 控制台 API → 启动 |
| **分段注释** | **一个都没有**（没有 `// =====` 之类的导航注释）—— 这是它难维护的主因 |
| 注入方式 | `content.js` 里 `script.src = chrome.runtime.getURL('page.js')`，**单个 `<script>` 标签** |
| 资源声明 | `manifest.json` 的 `web_accessible_resources.resources` 里列了 `"page.js"` |
| 打包 | `tools/build.js` 用**白名单 `INCLUDE`**（`page.js` 在列） |
| e2e 加载目录 | **仓库根目录**（`--load-extension=<repo root>`），**不是 `dist/`** |

按方法体关键词归类后的**行跨度**（这就是问题所在）：

| 域 | 方法数 | 行数 | 行跨度 |
| --- | --- | --- | --- |
| 答题 / 题目 | 99 | 3243 | **586 – 9860** |
| 任务点 / 调度 | 56 | 2293 | **502 – 9898** |
| 页面 / DOM | 52 | 1327 | **359 – 9448** |

## 2. 推荐方案：**分两阶段，第一阶段零行为风险**

### 阶段一：源码拆分 + 构建期拼接（**行为零变化**）

1. 新建 `src/page/` 目录，把 `page.js` **按现有物理行区间**切成若干段
   （例如每段 800–1200 行，建议 8–12 个文件）。
   **⚠️ 只按行切，绝对不要重排、不要改任何一行内容。**
   切点选在**方法边界**（`    _name: function (…) {` 上一行）上。
2. 每个文件加一段**头部注释**，写明：这一段原本是 `page.js` 的哪几行、里面有哪些方法
   （方法名可以脚本生成，330 个手抄不现实）。
3. 新增一个拼接脚本（建议 `tools/concat-page.js`），把 `src/page/*.js` 按文件名排序拼成
   根目录的 `page.js`。挂到 `package.json` 的 scripts 上（例如 `npm run concat`）。
4. **验收（这一条是阶段一的全部意义）**：
   拼接产物必须与拆分前的 `page.js` **逐字节相同**。
   做法：拆分前先 `cp page.js page.js.orig`，拆完拼回来后 `cmp page.js page.js.orig`。
   **不相同就说明你改动了内容 —— 回去修，别往下走。**
5. 确认 `npm test` + `npm run e2e` 全绿（理论上必然全绿，因为产物字节相同）。

**为什么先做这一步**：它把"拆分机制"（多文件 + 拼接 + 流程）建立起来，
而**完全不触碰行为**。后面阶段二无论怎么重组，都有这条"字节相同"的基线可以回退。

**这一步之后，下面这些文件全都不用改**（因为它们看的是根目录那个拼出来的 `page.js`）：
`manifest.json`、`content.js`、`tools/build.js` 的 `INCLUDE`、`web_accessible_resources`。

### 阶段二：按域重组（**有行为风险，靠 e2e 兜**）

1. 把方法按域搬到对应文件：`core.js` / `dom.js` / `media.js` / `quiz.js` / `tasks.js` /
   `log.js` / `config.js` / `captcha.js`。
2. **一次只搬一个域，搬完立刻跑 `npm run e2e`**（280 项，约 2 分钟）。
   **不要一次搬完再测** —— 那样出问题时你分不清是哪个域搬坏的。
3. 搬完每个域，在文件头补一段该域的说明：**这个域负责什么、和谁有耦合、有哪些坑**。
4. 全部搬完后，`page.js` 应当只剩：IIFE 外壳 + 常量 + 启动逻辑 + 各域文件的拼接位。
5. 补一份 `src/page/README.md`：模块地图（哪个域在哪个文件、各自负责什么、依赖关系）。

## 3. 硬性约束（违反会出事，逐条都有历史教训）

来自 `AGENTS.md` §2，拆分时必须原样保留语义：

1. **跨域 iframe 永远不要裸读 `.document`** —— 走 `_safeDocOf()` / `_safeWinDoc()`。
   裸读抛的 `SecurityError` 会**静默打断整个 tick 循环**，是最难查的一类 bug。
2. **新增 `await` 必须可超时** —— 任何永久悬挂都会让主循环死亡。
3. **删方法前 grep 全部调用点** —— 本项目真发生过"删了函数留着调用点"，
   4 处调用点里 3 处没 try/catch，**整条功能静默失灵**。
4. **提示词与 API 地址不许内联** —— 唯一真源是 `libs/prompt.js` 与 `libs/api-url.js`。
5. **`_getAttachmentWorkType` 的判断顺序不能动**：`isPassed` → `job:true` → `job:false` → 模块名推断。
6. **`_isJobCompleted` 拿不准时必须返回 `true`** —— 它喂给"放弃"计数，
   误判成"没完成"会把必做任务点跳过。
7. **跳过用户的任务点必须留日志 + 可恢复** —— 静默永久跳过不可接受。
8. **`_runTick` 的判定顺序就是仲裁顺序** —— 改动它是高风险操作。
9. **`window.xxtAI` 是给用户的手动调试入口**（`xxtAI.skipQuiz()` / `diagnosePopup()` /
   `taskGiveUpList()` 等），**必须保留**。注意有些方法"看起来没人调用"，
   其实是被用户手动调的 —— 别当成死代码删掉。

## 5. ⚠️ 已知会骗你的坑（本仓库实测踩过，每条都制造过"假成功"）

这些坑的共同点是：**让你以为验证过了，其实没有**。请逐条防。

| 坑 | 表现 | 怎么防 |
| --- | --- | --- |
| **CRLF 锚点** | 脚本里锚点写 `\n`，而文件是 **CRLF** → `split/join` **静默变成空操作**，文件根本没改，断言却"通过"了 | 改完**先 grep 回读确认落盘**，再解读结果。文件是 LF 还是 CRLF 用 `indexOf('\r\n') !== -1` 判，别猜 |
| **`&&` 链静默断掉** | `npm test && cp 备份 && 注入 && npm run e2e` —— `npm test` 失败 → **后面全没执行**，但输出里照样有后面那句日志，于是你以为验证过了 | 前置条件先单独跑；**看输出里有没有出现注入那一步的日志** |
| **`node -e` 内联大段中文** | shell 单引号 + JS 双引号 + 中文里的引号互相截断，报莫名其妙的 `Expected ',', got '某段中文'` | **用 Write 写一次性补丁脚本**，脚本里中文一律用 `「」`，跑完 `rm` |
| **测试间共用可变状态** | 新测试往共用对象写状态 → 撞坏后面用同一个对象的断言 | 新测试**自带隔离**（造自己的合成对象），别改共用的 |
| **断言不可能失败** | 语法完全正常，只是恰好永远为真（例如"表单被清空时把答案记成错的"—— 那时根本没有可记的答案） | **每条新断言都做反向验证**：临时注入一个已知错误，确认它**真的会红** |

**关于反向验证**：注入之后**先确认注入真的落盘**，再去解读断言结果。
"断言通过了"本身就是线索 —— 可能是注入没生效。

## 8. 最后一句

**这个任务的价值不在"文件变小了"，而在"以后改一个域不用在 9899 行里找"。**
所以判断做得好不好，看的是：**下一个人能不能在 30 秒内定位到他要改的那个域**。
如果做不到，那只是把一个大文件切成了几个没有导航的碎片，等于白做。

**做完请自问**：`README.md` 的定位表能不能让人从"我要改倍速"直接跳到 `media.js`？
